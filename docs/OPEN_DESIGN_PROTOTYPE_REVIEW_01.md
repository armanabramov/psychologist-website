# UX/UI-review прототипа Open Design — psy.html

**Дата:** 2026-11-01  
**Источник проверки:** загруженный исполнителем локальный файл `psy.html`, **не опубликованный в репозитории**.  
**Статус:** **пользователю нравится выбранная визуальная концепция; сохраняем стиль и развиваем точечно.** Заказчица ещё не утверждала визуал и содержание; реальные материалы придут после брифа.

## Метод проверки

- Изучены фактические HTML, CSS, русские тексты и JavaScript.
- HTML отрендерен в Chromium (Playwright) на **1440×900, 1024×768, 768×1000, 390×844, 320×720** с полностраничными скриншотами. В отличие от старого RENZ-аудита здесь **mobile проверен визуально**.
- Проверены ширина прокрутки, размеры шрифтов, якоря, раскрытие мобильного меню, Escape, FAQ, базовые сценарии CTA. Копирование текста в локальной непроверенной среде открыло ручной fallback; это не подтверждённый дефект HTTPS-сайта.
- Не проводились реальная отправка заявки, внешние интеграции, комплексный WCAG-аудит, оценка SEO и фотографий — их нет в файле.

## Общий вердикт

**Основа сильная, редизайн не нужен.** Интерфейс реализует визуальный язык RENZ без клинической стилистики: единый Onest, белые поля, нейтральные светлые панели, ограниченные радиусы, лаконичный русский текст и мягкая компоновка. Субъективно **8.5/10 за визуальную основу**, не за готовность к публикации.

## Палитра — сравнение с исходными ориентирами Dulux

В CSS уже **присутствуют точно те пять цифровых ориентиров**, которые обсуждались раньше и передавались Open Design текстом:

| Dulux | В CSS | Роль |
|---|---|---|
| 20YY 38/225 | `#BDA17F` | `--accent` |
| 40YY 25/074 | `#888073` | `--taupe` |
| 83YY 45/055 | `#B3B2A8` | `--surface-muted` / границы |
| 81YY 73/041 | `#E1DFD7` | `--surface` |
| 90YR 06/001 | `#464545` | `--text` / `--button` |

Дополнительно белый `#FFFFFF` и производная светлая поверхность `#F7F6F4` (из `color-mix`).

На полном desktop-скриншоте основные пиксели: белый ≈72.4%, `#E1DFD7` ≈16.5%, `#F7F6F4` ≈6.7%, `#464545` ≈1.3%. Это **фактические доли изображения, не дизайн-токенов**. Цветовой баланс очень светлый; `#888073` и `#BDA17F` используются лишь как небольшие акценты.

**Вывод:** по переданным ранее HEX попадание точное, но **по фотографии клиентских образцов совпадение пока не подтверждено**: изображение не было прикреплено генератору, цифровые HEX получены из предварительной трактовки кодов. Добавить фото Dulux и запросить **color-only audit** без изменения сетки/типографики.

### Контраст отдельных пар (расчёт WCAG)

- `#464545` / белый: ≈9.56:1; / `#E1DFD7`: ≈7.16:1.
- `#625E58` / белый: ≈6.44:1; / `#E1DFD7`: ≈4.83:1.
- `#888073` / белый: ≈3.90:1 — для обычного текста **недостаточно**; использовать в декоративных деталях/крупном тексте с проверкой.
- `#B3B2A8` / белый: ≈2.13:1 — не применять как цвет мелкого текста.
- Данные относятся к отдельным сплошным парам и не являются общим отчётом доступности.

- ✅ Нет горизонтального переполнения на пяти проверенных размерах.
- ✅ Мобильное меню открывается и закрывается, якорь его закрывает, Escape тоже.
- ✅ FAQ раскрывается native `details/summary`.
- ✅ Есть skip-link, фокусные состояния и `prefers-reduced-motion`.
- ⚠️ На mobile страница получается довольно длинной: около 7.9–8.5 тыс. px. Секции запросов и «Обо мне» занимают много места. Не уменьшать читаемый текст; искать компактность через редактуру/композицию, не добавляя сложные анимации.
- ⚠️ Copy-message CTA на локальном `about:blank` / небезопасном origin переключился в fallback ручного копирования, потому что `navigator.clipboard` недоступен. Проверить настоящую HTTPS-среду отдельно. Этот механизм всё равно не лучший основной сценарий записи.

## Сильные решения, которые надо закрепить

1. Ровная и спокойная сетка без декоративных асимметрий.
2. Современный Onest по всей странице; desktop body 18px, mobile 16px.
3. Согласованная система поверхностей, радиусов и CTA.
4. Хорошие повседневные формулировки запросов, вместо маркетинговых обещаний.
5. Не выдуманы дипломы/отзывы/имя. Указан демонстрационный характер услуг.
6. Рабочая базовая адаптивность, клавиатурные и нативные элементы.

## Приоритеты доработки в Open Design

**P0 — не менять понравившийся дизайн целиком:**
1. **Color-only итерация по исходной фотографии Dulux.** Сохранить Onest, layout, компоненты, объём текста, отступы и цветовые роли; предложить корректировку распределения и значений только если фото действительно требует. Дать «было/стало» по токенам.
2. **Сценарий записи.** Сейчас «Записаться» только прокручивает к панели с копируемым текстом. Для прототипа заменить её на аккуратное представление согласуемых каналов обращения (мессенджер/email) с явным демостатусом; не создавать фиктивно работающие формы и не вставлять действительные чужие контакты.
3. **Портреты.** Две большие монограммы `ИФ` в hero и About — нормально для черновика, но не для окончательного визуального теста. Использовать настоящие фото заказчицы с разрешения, либо **чётко маркированные** демонстрационные визуалы. Подготовить два варианта композиции с фото, при этом не менять остальную страницу.

**P1 — привести содержание к профессиональному и правдоподобному:**
4. Hero: H1 «Можно начать с разговора» эмоционально приятен, но реальная специализация/формат сейчас только в мелких подписях. Сохранить интонацию, сделать «кто, с чем помогает, как записаться» ясным за 5 секунд.
5. Образование: заменить обобщённые заглушки компактными подтверждёнными данными **после брифа**. Сейчас нет фактов; не заполнять вымышленными дипломами.
6. Услуга: оставить одну карточку, если одна услуга; не добавлять вторую для красоты. `50 минут / 4 000 ₽` явно демонстрационны и должны быть заменены.
7. Демо-ограничения повторяются в нескольких блоках и ломают атмосферу цельной страницы: оставить одну общую заметку о прототипе, остальные примечания вынести в рабочий документ, **не маскируя** подлинные и демонстрационные факты.

**P2 — после первого ревью/брифа:**
8. Решить, нужен ли блок отзывов / «ПроДокторов» и статьи. Не генерировать отзывы и не раздувать страницу без материалов.
9. Оптимизировать мобильную длину аккуратно: 6 однотипных карточек на 390px = около 1314px раздела; «Обо мне» ≈1060px. Можно сжать пустые внутренние зоны, но не уменьшать основной кегль.
10. Перед запуском: настоящие контакты, политика персональных данных, проверка ссылок, SEO, производительность, тест форм и совместимость.

## Готовое краткое задание на следующую итерацию

> Продолжай работу с **существующим** Open Design-прототипом `psy.html` — **не делай редизайн**. Нам нравится текущая сетка, Onest, белые поля, цвета-поверхности, скругления, типографика и порядок разделов. Сохрани их как baseline. Сначала приложенную фотографию исходных пяти образцов Dulux сопоставь с текущими CSS-токенами и покажи цветовой diff; не меняй палитру только потому, что хочется больше цвета. Затем доработай **только** (1) персональный hero с чёткой специализацией и продуманным использованием фотографии, (2) механизм контакта после «Записаться», (3) сокращение повторяющихся демо-предупреждений с сохранением честного статуса условных фактов, (4) мобильную компоновку, особенно длину блоков запросов и About, без уменьшения базового шрифта. Все 8 смысловых секций оставить, отзывы не выдумывать, статьи не добавлять автоматически. Проверь desktop 1440, tablet 768, mobile 390 и 320. Покажи список изменённых элементов, прежде чем считать итерацию завершённой.

**Важное уточнение:** пользователь одобрил именно визуальное направление **в качестве основы для дальнейших доработок**, но не считает макет готовым и не согласовал его с заказчицей.
