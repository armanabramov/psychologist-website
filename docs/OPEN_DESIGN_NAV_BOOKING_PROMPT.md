# Open Design — точечная доработка меню и записи по видео RENZ

**Дата:** 2026-11-01  
**Статус:** утверждённое пользователем направление референса; промпт для **будущей точечной правки существующего прототипа**. Изменять UI сейчас самостоятельно не требуется; подготовить задание для Open Design.  
**Входной файл:** видео пользователя «Запись экрана 2026-11-01 в 01.32.25.mov» (45.48 с, 2226×1522, скринкаст DevTools). Видео **не опубликовано в репозитории**.  
**Прототип:** `psy.html` в текущем проекте Open Design; **сохранить текущую UI-концепцию**, Onest и Dulux.  
**Контекст и спецификации:** [OPEN_DESIGN_PROTOTYPE_REVIEW_01.md](OPEN_DESIGN_PROTOTYPE_REVIEW_01.md), [PALETTE_REVIEW_01.md](PALETTE_REVIEW_01.md).  
**Важно:** пользователь решил **оставить текущую палитру без изменений**. Эта задача — исключительно меню и заявка.

## Что подтверждается видеозаписью (не предположение)

Секунды ориентировочные:
- **0–2 с**: мобильный профиль RENZ в DevTools на ~320 CSS px. У нижнего края — **фиксированная floating-панель**: слева pill-CTA «Консультация», справа отдельная группа из нескольких иконок, включая hamburger.
- **2–14 с**: после CTA появляется затемнение фона и крупная белая **модальная форма** с округлыми углами и крестиком закрытия. Заголовок «Запись на консультацию». В оригинале четыре поля: **врач, дата, имя, номер телефона**, согласие/политика и «Отправить запрос». В интерактивном состоянии календарь выпадает из поля даты. Чёрное выпадающее меню в районе 8–12 с — **интерфейс браузерного/системного автозаполнения**, а не продуктовый UI RENZ; не копировать.
- **16–21 с**: при нажатии hamburger открывается **bottom sheet / мобильное меню**, основная страница темнеет. Белая панель с округлённым верхом поднимается снизу. Большие текстовые ссылки («Главная», «Специалисты», «Контакты») и внизу контактный блок (телефон, адрес). Фиксированная нижняя панель остаётся визуально поверх; hamburger становится круглым крестиком. Закрытие возвращает обычную страницу.
- **28–30 с**: desktop клиники: обычная верхняя шапка и кнопка консультации.
- **32–42 с**: desktop форма открывается **как правый выдвижной drawer во всю высоту**, фон затемнён. Сверху логомарка и крестик; в середине заголовок и компактные округлые поля в сетке; ниже юридическая подпись; внизу CTA с отдельной круглой стрелкой. Календарь открывается поповером. Попытка отправить незаполненные обязательные поля подсвечивает их.
- **42–45 с**: drawer закрывается и основной desktop возвращается.

### Важно для адаптации

Видео относится к сайту **клиники** с каталогом специалистов, личным кабинетом, поиском и прочими функциями; переносить их на сайт **одного психолога** нельзя. Пользователь отдельно запретил иконки поиска/профиля/корзины и пункт «Специалисты», **поле «Врач» в заявке также не нужно**.

В видео мобильный dock остаётся видимым и при модальной форме, где слева кнопка меняется на «Назад». Для нашего лаконичного сайта допустимо обеспечить схожий визуальный язык, но сделать поведение проще и доступнее: dock оставить над bottom sheet меню, а **при форме скрывать или заменять явно понятным «Назад»**, чтобы он не перекрывал кнопку отправки.

## ГОТОВЫЙ ПРОМПТ ДЛЯ OPEN DESIGN

Работай **в уже существующем текущем Open Design-проекте сайта одного частного психолога** и редактируй **текущую версию** прототипа `psy.html`. **Не создавай новый сайт, другую концепцию, новую палитру или новые секции.**

Задача — реализовать **две точечные интерактивные доработки** по приложенной видеозаписи RENZ Clinic: (1) фиксированное нижнее мобильное меню и открывающийся из него bottom sheet, (2) адаптивную панель записи на консультацию, которая выезжает справа на desktop и становится модальным sheet на mobile.

Сначала проанализируй вложенное видео, особенно фрагменты ~0–2, 2–14, 16–21 и 32–42 с. Не пытайся копировать всю клинику; возьми **форму и механику** элементов.

### A. Неприкосновенная база

СОХРАНИТЬ без изменений:
- общую композицию одностраничника, порядок и содержание существующих секций;
- шрифт **Onest**, типографические размеры, визуальную иерархию;
- систему мягких радиусов, карточек, светлых поверхностей, воздуха и анимаций;
- текущую **палитру Dulux**: `#BDA17F`, `#888073`, `#B3B2A8`, `#E1DFD7`, `#464545`, белый;
- текущие якоря: `#top`, `#requests`, `#about`, `#education`, `#consultations`, `#process`, `#faq`, `#contact`;
- desktop header, только при необходимости адаптировав его кнопку «Записаться» для открытия формы.

Никаких новых оттенков бордового или розового RENZ. Не смешивай с предыдущими отклонёнными концепциями. Не превращай сайт в SaaS-dashboard.

### B. Мобильный fixed bottom dock (ширина ≤ 767/768px)

Замени нынешний **верхний мобильный hamburger-dropdown** на **плавающий фиксированный нижний dock**, вдохновлённый видео.

Визуальная структура dock:
- СЛЕВА: единственная выразительная большая капсульная кнопка **«Записаться»**, в основном тёмном Dulux `#464545` с читаемым белым текстом. Можно использовать стилистику RENZ с маленькой стрелкой, **если не перегружает**.
- СПРАВА: одна круглая или почти круглая кнопка **hamburger** с тремя линиями; при открытии меняется на **X**. Обе части имеют общую согласованную систему радиусов.
- Допустим полупрозрачный светлый фон/тонкая граница вокруг группы, без тяжёлого shadow, в логике RENZ.
- **Строго никаких** значков поиска, корзины, личного кабинета, уведомлений, фильтров, страницы врачей, отдельных быстрых действий.
- Dock плавает над нижним краем, ориентир 12–20px отступов сбоку/снизу + учёт `env(safe-area-inset-bottom)`. Элементы удобны для касания, область нажатия не менее 44×44 CSS px.
- Dock остаётся доступным при прокрутке; **не должен перекрывать контент/FAQ/последний CTA**: добавь нижний отступ страницы на mobile. На ширине 320px всё должно помещаться.
- Верхнюю мобильную шапку можно оставить лаконичной с именем/названием, но **не дублировать в ней второй hamburger**.

### C. Открытие мобильного меню — bottom sheet

По клику на hamburger:
1. Поверх страницы появляется мягкий тёмно-серый **backdrop** с небольшой прозрачностью, без непрозрачного чёрного слоя.
2. **Снизу вверх** плавно появляется белая/светлая панель с аккуратно округлёнными верхними углами. Визуально как на видео: большая чистая панель, просторные вертикальные текстовые ссылки, без иконок.
3. Ссылки только на секции **этого одностраничника**:
   - Главная → `#top`;
   - С чем работаю → `#requests`;
   - Обо мне → `#about`;
   - Консультации → `#consultations`;
   - Вопросы → `#faq`.
   В нижней информационной части можно дать «Контакты» → `#contact` и примерный контактный способ/часы только если данные подтверждены. Пункт «Специалисты» и ссылки на карточки врачей **НЕ создавать**.
4. Навигация — крупный Onest, комфортный межстрочный интервал; в нижней части можно выделить отдельный небольшой контактный блок вместо телефона и адреса клиники из видео. **Не выдумывать реальные телефон, адрес, email.**
5. Панель с учётом высоты содержимого, max-height около `85dvh`, прокрутка внутри при необходимости; не перекрывать собственные ссылки. Dock остаётся внизу поверх панели, hamburger становится кнопкой закрытия, CTA остаётся узнаваемым. Если пользователь нажимает CTA во время открытого меню — сначала закрой меню, потом открой форму.
6. Клик по якорю закрывает меню и плавно прокручивает к соответствующей секции; учитывай sticky header.
7. Клик по backdrop, кнопке X, клавиша Escape — закрывают меню. При открытии блокируй прокрутку страницы, при закрытии восстанавливай. Правильно управляй фокусом, ARIA (`aria-expanded`, `aria-controls`) и его возвратом.

Не создавать отдельную страницу меню и не делать аккордеон ссылок.

### D. Форма записи — визуальный образ RENZ, но для ОДНОГО психолога

Все существующие CTA «Записаться» в шапке, hero, услуге и нижней секции должны вести в **один и тот же модальный сценарий**, а не в разные формы и не в копирование текста из нынешнего прототипа.

**Desktop ≥ 769px:** справа выезжает светлый drawer шириной ориентировочно 400–480px, высотой 100dvh. Основная страница затемняется, но остаётся узнаваемой. Панель белая, аккуратные поля, фирменный скруглённый CTA со стрелкой. Сверху маленькое имя/wordmark психолога (НЕ логотип RENZ), сверху справа крестик. Середина: заголовок «Запись на консультацию» и одна короткая фраза о следующем шаге. Кнопку отправки визуально держи ближе к низу drawer, как в видео, но при маленькой высоте панели всё должно оставаться достижимым.

**Mobile ≤ 768px:** форма открывается поверх затемнённого сайта в крупной аккуратной светлой **модальной панели** со скруглениями, похожей на видео. Поля перестраиваются в одну колонку, содержимое прокручивается, крестик виден всегда. Не перекрывать кнопку подтверждения мобильным dock: при открытой форме лучше **скрыть dock** (или заменить на понятный «Назад», если действительно аккуратнее), а не оставлять одновременно две конкурирующие CTA. На 320px сохранить поля, отступы и закрытие.

**Поля первой демо-версии, без выбора врача:**
- `Имя` — обязательное;
- `Номер телефона` — обязательное; с корректным `type=tel` и доступной маской/подсказкой, не навязывающей недействительный номер;
- `Желаемая дата` — **необязательное** поле с аккуратным popover-календарём, как в видео. Чётко поясни: это **пожелание, а не подтверждённая запись**, реальное время согласуется дополнительно.
- Если для композиции действительно необходимо четвёртое поле, можно добавить **необязательный** способ связи, но **не добавлять** вопрос «С чем вы обращаетесь?» или поля чувствительных личных/медицинских данных.

Не делать поле «Врач», список специалистов, выбор медицинской услуги, кабинет, логин или регистрацию. Не выдумывать цены/расписание, медицинские лицензии или слот реально доступной записи.

Визуально: 2 компактные колонки там, где хватает ширины (например, `Имя/Телефон`), на mobile — **все поля друг под другом**. Нейтральные округлые поля с ясными границами и заметными фокусными состояниями. Календарь должен открываться поверх формы, не обрезаться панелью и не выходить за viewport.

Снизу: очень короткое честное пояснение, что произойдёт после обращения. Кнопка **«Отправить заявку»** с капсульной формой и круглой стрелкой по мотивам RENZ. Небольшая подпись о данных/политике — без вымышленной юридической страницы.

**Демонстрационный характер:** реального бэкенда, email/API, обработчика персональных данных и подтверждения времени пока нет. В текущем интерактивном прототипе НЕ отправлять данные наружу, НЕ имитировать успешную запись и НЕ делать ложное сообщение «мы получили заявку». При попытке отправки валидируй обязательные поля, а для заполненной формы показывай ясную подсказку **«Это демонстрационный прототип. Отправка заявок будет подключена после согласования»**. Перед production потребуется настоящий канал отправки, юридические документы и согласие на обработку данных. Не собирать в демо реальные конфиденциальные сведения.

### E. Интерактивность и технические критерии

- Открытие/закрытие menu и form с мягким переходом 200–300ms; `prefers-reduced-motion` без анимаций.
- Overlay клики, Escape, правильный z-index, scroll lock, focus trap внутри активной модальной формы и восстановление фокуса на CTA после закрытия.
- Не допускается два overlay одновременно; открытие формы закрывает bottom menu.
- На desktop верхнее меню остаётся читаемым, а все «Записаться» открывают справа один drawer.
- На mobile dock видим при скролле, bottom sheet сверху dock, форма не конфликтует с ним.
- Не допускать горизонтального скролла, обрезания кнопок/календаря/текста на 1440px, 768px, 390px, 320px.
- Визуально проверить (не только CSS) как минимум: обычный экран, открытое меню, закрытие меню, открытая форма, календарь, валидация, закрытие формы, возврат страницы; отдельно desktop/mobile.
- Состояния кнопок соответствуют первоначальному UI-языку `psy.html`, цвета и контраст остаются в Dulux.
- Не менять desktop/mobile hero, запросы, About, образование, услуги, FAQ и footer ради этой задачи. Не заменять фотографии/заглушки сейчас — они придут в следующем этапе проекта.

### F. Порядок выполнения

1. Сначала **изучи приложенное видео** и **существующий макет**. Не начинай с пустого проекта.
2. Реализуй **только bottom dock + mobile menu + desktop/mobile booking drawer/modal** в текущих дизайн-токенах.
3. Протестируй состояния по видео, проверь все CTA, адаптив, фокус, scroll lock и валидацию.
4. Проведи краткий `impeccable`-аудит при доступности skill; он не должен делать полный редизайн.
5. Верни ссылку на **обновлённый тот же прототип** (а не новую самостоятельную страницу), desktop/mobile скриншоты трёх ключевых состояний и список конкретных сделанных изменений/ограничений.

**Главное:** текущий дизайн исполнителю очень нравится. Не перегенерируй весь сайт. Это **точечная UX-доработка** с сохранением утверждённого направления.
