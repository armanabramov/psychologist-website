# Аудит палитры v1 — перед следующими дизайн-правками

**Дата:** 2026-11-01  
**Статус:** только исследование цвета. Пользователь просил **не менять дизайн сейчас**: сначала палитра, затем две фотографии и источник профессиональных данных, затем дизайн-доработки.

## Исходные материалы

- Проверен загруженный локальный прототип `psy.html`: CSS `:root`, использование токенов и сделанные ранее Chromium-скриншоты.
- Найдена исходная фотография палитры клиента: название исходного локального файла `PHOTO-2026-10-08-12-07-27.jpg`. **Само изображение в публичный GitHub не загружаем**.
- Важно: фотография — стилизованная сцена с освещением, компрессией и, возможно, полупрозрачными цветовыми накладками. Цвета отдельных пикселей **не являются нормативными HEX Dulux**.
- Способ проверить соответствие намерению заказчицы: **сопоставить текущую страницу, исходное изображение и образцы в Open Design**; при необходимости подготовить только пробную цветокоррекцию, не обновляя весь layout.

Вспомогательные токены:

- `--text-secondary: #625E58`
- `--button-text: #FFFFFF`
- `--surface-soft: color-mix(in srgb, #E1DFD7 28%, #FFFFFF)`, но этот токен **не используется**; у карточек встречается hardcoded `#F7F6F4`.

Пять исходных ориентиров Dulux в `:root` уже совпадают с прежним ТЗ **точно по HEX**. Это не подтверждает совпадение с визуальным настроением фото или реальными красками.

## Визуальное сравнение с фотографией, не палитра для реализации

Для иллюстрации того, почему фото кажется темнее, взяты медианные цвета участков накладок, исключая видимые надписи, но не возможную прозрачность/свет:

| Код | Текущий цифровой ориентир | Пиксельный медианный цвет на фотографии (только для сравнения!) |
|---|---|---|
| 20YY 38/225 | `#BDA17F` | ~`#A88461` |
| 40YY 25/074 | `#888073` | ~`#6E5E52` |
| 83YY 45/055 | `#B3B2A8` | ~`#A49B8D` |
| 81YY 73/041 | `#E1DFD7` | ~`#CCC7BC` |
| 90YR 06/001 | `#464545` | ~`#141312` |

**КРИТИЧНО:** эти последние пять HEX **не предлагать как новый набор сайта** — это цвета кадра, включая фотографическую обработку, а не точная стандартизированная палитра. Особенно значение `#141312` легко превратит интерфейс в чрезмерно контрастный чёрно-белый.

Главная визуальная разница: исходная картинка выглядит теплее, темнее и землистее, чем светлая UI-палитра. При этом пользователь одобрил текущий стиль, поэтому не требуется автоматическая «покраска под фото».

## Распределение цвета в готовом desktop-рендере

Результат предыдущего анализа пикселей `psy_1440.png`:
- белый `#FFFFFF`: ~72.4%;
- фон `#E1DFD7`: ~16.5%;
- дополнительный светлый оттенок `#F7F6F4`: ~6.7%;
- `#464545`: ~1.3%; остальные — текст/границы/сглаживание и мелкие цвета.

То есть **два более насыщенных цвета Dulux практически не формируют вид страницы**. Они есть в токенах, но используются лишь в миниатюрных декоративных деталях. Это может быть и сознательно правильным минималистичным решением. Нельзя утверждать, что цвета в целом «не попали», лишь по ощущению.

## Контраст — ограниченные расчёты для сплошных пар

- `#464545` на белом ~9.56:1, на `#E1DFD7` ~7.16:1: хорошо.
- `#625E58` на белом ~6.44:1, на `#E1DFD7` ~4.83:1: годится для обычного текста при указанных фонах.
- `#888073` на белом ~3.90:1: **не годится для обычного небольшого текста** по порогу 4.5:1.
- `#B3B2A8` на белом ~2.13:1: годится как декоративный фон/граница только после контрастной проверки, не текст.
- Это не автоматический WCAG-аудит страницы, лишь примеры пар.

## Рекомендация для цветового этапа

1. **Сохранить** layout, Onest, структуру, скругления и текущую светлую основу. У пользователя положительный отзыв.
2. Сравнить **три материала рядом**: исходное фото Dulux, текущий первый экран, текущие светлые панели «Обо мне» / контакты. Не решать только по одному цветному чипу.
3. Цветовой эксперимент, если желателен: **небольшое усиление** присутствия среднего/тёплого Dulux в 1–2 фрагментах интерфейса, а не перекраска всего. Предложить 2 схемы распределения: A — текущая белая воздушность; B — немного больше серо-тауповых поверхностей. Все цвета только из исходных кодов/производных.
4. В Open Design запросить **color-only review**: сначала рекомендации и скриншоты сравнения, **не менять сам прототип** без выбора пользователя.
5. Если актуальны официальные численные HEX для Dulux, проверить каталог и способ отображения в браузерах — декоративная фотография не точный колориметрический источник.

## Порядок дальнейшей работы (подтверждён пользователем)

1. **Сейчас:** палитра, без правок дизайна.
2. **Затем:** пользователь пришлёт **две фотографии психолога** + **источник актуальных сведений**; проанализировать достоверность и то, как фотографии лягут в две медиа-зоны, не публикуя персональные изображения в публичном репозитории без разрешения.
3. **После этого:** улучшение дизайна и UX (hero, контент, запись, мобильная компоновка).

### О мобильном меню

Пользователь особо отметил, что в Open Design ему нравится **нижняя закреплённая мобильная навигация**, её следует сохранить, а пункт «Специалисты»/лишний профиль ему не нужен. Он пообещал прислать **скриншоты меню и записи**.

При этом **в проверенном загруженном `psy.html`** реализован переключатель «Меню» **сверху**, раскрывающий ссылки `#requests/#about/#consultation/#faq`, а не закреплённый снизу dock. Это **разница между пользовательским описанием preview и текущим HTML**, а не доказанный баг или повод переделывать навигацию. Сверить по скриншотам позже, **не менять сейчас**.
